# React Native Upgrade & Maintenance Guide

This document outlines the standard operating procedure for upgrading the bare-workflow React Native application in `mobile/`.

---

## 1. Upgrade Philosophy & Versioning Matrix

The LatexAI mobile client uses the React Native bare workflow with the React Native Community CLI. Upgrades should be conducted conservatively, typically staying on the latest stable minor release and applying security patches immediately.

### Tooling Baseline (Current v0.87.1)
- **Node.js**: `^22.13.0` or `>=24.0.0` (Node 22 LTS or Node 23 supported)
- **Java / JDK**: OpenJDK 17 (required by Gradle 8+)
- **Android Gradle Plugin (AGP)**: 8.x
- **Android SDK**: API 35 (Compile SDK), API 24 (Min SDK)
- **Xcode**: 16.0+ (iOS 15.1+ deployment target)
- **CocoaPods**: 1.14+
- **React**: 19.x

---

## 2. Upgrade Step-by-Step Procedure

### Step 1: Utilize the React Native Upgrade Helper
Always compare the current version with the target version using the community diff tool:
👉 [React Native Upgrade Helper](https://react-native-community.github.io/upgrade-helper/?from=0.87.1)

Inspect all changes across:
- `android/build.gradle` and `android/app/build.gradle`
- `android/gradle/wrapper/gradle-wrapper.properties`
- `ios/Podfile`
- `ios/LatexAI.xcodeproj`
- `metro.config.js` and `babel.config.js`

### Step 2: Create a Dedicated Upgrade Branch
```bash
git checkout -b chore/rn-upgrade-0.xx.x
```

### Step 3: Check Native Dependency Compatibility
Audit third-party native libraries for compatibility with the target React Native version:
- `react-native-screens`
- `react-native-safe-area-context`
- `react-native-gesture-handler`
- `react-native-reanimated`
- `react-native-svg`
- `react-native-keychain`
- `react-native-bootsplash`
- `react-native-config`
- `@react-native-async-storage/async-storage`
- `@react-native-community/netinfo`

### Step 4: Apply Diff to Root and Config Files
Apply the changes generated by the Upgrade Helper to:
- `package.json`
- `metro.config.js`
- `babel.config.js`
- `tsconfig.json`

Run:
```bash
npm install
```

### Step 5: Android Build Verification
1. Clean Gradle caches:
   ```bash
   cd android
   ./gradlew clean
   cd ..
   ```
2. Build Android debug APK:
   ```bash
   npm run android
   ```
3. Verify that native plugins (`react-native-config`, `react-native-bootsplash`, etc.) resolve properly without Gradle deprecation warnings.

### Step 6: iOS Build Verification (macOS)
1. Clean and reinstall CocoaPods:
   ```bash
   cd ios
   rm -rf Pods Podfile.lock
   bundle exec pod install --repo-update
   cd ..
   ```
2. Build and run in simulator:
   ```bash
   npm run ios
   ```

### Step 7: Automated Test & Quality Gates
Execute automated verification scripts:
```bash
npm run typecheck
npm run lint
npm test -- --coverage
```

### Step 8: Architecture & New Architecture (Fabric / TurboModules) Verification
When upgrading across major architecture versions:
- Verify that custom and third-party native modules have CMake / C++ codegen enabled if running in `newArchEnabled=true` mode.
- In `android/gradle.properties`, confirm `newArchEnabled` settings.

---

## 3. Rollback & Emergency Recovery

If an upgrade triggers breaking native toolchain incompatibilities:
1. Revert to the previous clean commit:
   ```bash
   git reset --hard HEAD
   git clean -fd
   ```
2. Clear Metro cache:
   ```bash
   npm start -- --reset-cache
   ```
3. Reinstall original package lock:
   ```bash
   npm ci
   ```
